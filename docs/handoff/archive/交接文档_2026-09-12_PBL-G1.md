## 一、最重要的一件事：Queue 前提对 Arena B 不成立

Queue 写「**A/B Runtime 已存在**」。**这句话对 B 是错的。**

PBL-B1 已按其自身的「停止条件」终止：390 宽竖屏的横向接敌轴只有 **366px**，而 1v1 共享测试车
真实外接框总宽 **410–498px**，两车几何上放不下（缺口 44–132px）。B1 的结论是 **0 行生产代码**
（commit `8c27cd0`，见 `交接文档_2026-09-12_PBL-B1-STOP.md`）。

因此本 Lab 里的 **Arena B 仍然只是 PBL-F1 的占位舞台，不是物理运行时**。

**这个事实直接决定了 G1 的形态**：G1 要求「证明两边除允许差异外没有隐藏参数差异」。
对 A 可以完整证明；对 B —— 没有可证明的对象。本门禁对此**不掩饰、不降级、不伪造**：

- B 的 6 步中 3 步在执行层面为 `observed=blocked`；
- B 步骤**绝不 Start**（不拿占位舞台冒充对照，不产出任何「B 的真实表现」数据）；
- 门禁总体结论按实际为 **`blocked`，不是 `pass`**（E2E G10 专门断言这一点）。

## 二、交付内容

### 2.1 新增 `src/lab/portraitBattleLab/gate.ts`（纯逻辑：无 DOM / 无 fs / 无副作用）

| 导出 | 作用 |
|---|---|
| `PBL_ALLOWED_ARENA_DIFFERENCES` | 允许差异**集中登记**，恰好 3 类：`arena-geometry` / `physics-interpretation` / `movement-adapter`；每类登记**落点文件 + 落点符号** |
| `allowedDifferenceFiles()` | 允许差异的全部落点文件（去重，供守卫比对） |
| `PBL_ARENA_RUNTIMES` | 已落地的 Arena 运行时 —— **门禁可用性的唯一来源**（目前只有 `A`） |
| `PBL_BLOCKED_ARENAS` | 未落地 Arena 的阻塞原因（B 的原因为 B1 停止条件原文摘要） |
| `arenaRuntimeAvailable()` / `arenaAvailability()` | 可用性查询（派生，非写死） |
| `PBL_GATE_SEQUENCE` | Queue 必改 2 的 **6 步逐字对齐**（A/B 交替）；未写明字段在 `assumed` 显式暴露 |
| `gateStepPlan()` | 某步是否真能跑；`blocked` 时 **`plan = null`**（不伪造可运行的 B 战斗） |
| `auditSharedCombatData()` | **共享配置审计**：2 Loadout × 3 Encounter = 6 组合 |
| `auditSpawnPlan()` | 单计划审计（单独导出 → 门禁自身可被反向验证） |
| `gateResidue()` | 切场 / Reset 的**零残留判据** |
| `gateSummary()` | `fail` / `blocked` / `pass` 三分支 |

**审计怎么做到不是空转的**：对每个实体，用一个**独立的 snapshot id** 重走正式链路
`buildSnapshotFromDraft` → `validateSnapshot` → `resolveSnapshot`，再直接从正式
`registry.functionals` 的 `behaviorParams` 重算 `contactDamage / projectileDamage / cooldownMs /
projectile{radius,mass,speed}`，最后与 `SpawnPlan` 里的值**逐字段 JSON 比对**。
计划里任何「解析后被就地覆盖」的战斗数值都会暴露。

### 2.2 `lab.ts` 接线

- 新增 `Gate` 按钮组：**`Gate 下一步`**（按固定顺序推进一步）/ **`Gate 清空`**（游标归零）。
- `Gate 下一步` 的执行语义：
  1. 审计未通过 → **拒绝推进**；
  2. 依次 `setArena` → `setLoadout` → `setEncounter`（每次配置变更都由状态机强制清场）；

  4. 该 Arena 有真实运行时 → `Start`；否则判 `blocked` 且**不 Start**。
- 新增 DOM 对照面板（`.pbl-gate`）—— **必须位于 canvas 之外**，否则会污染 E2E 的分层像素分类。
- `probe()` 新增 `gate` 字段（审计结果 / 允许差异 / 6 步顺序 + 每步 planned+observed / 游标 / 切场残留 / verdict / 可用性）。

## 五、录屏时建议的固定操作顺序

> 目的：一次点击序列即可走完 Queue 规定的 6 步顺序，且每一步的配置、清场、执行结果都写在面板上。

0. 打开 `http://localhost:5173/portrait-lab.html`，**等画面稳定**（`READY（A1 俯视场 · t=0 静止）`）。
   先读一眼门禁面板：`verdict=blocked`、`审计=PASS`、`快速验证顺序（已推进 0/6）`。
1. 点 **`Gate 下一步`** → 第 1 步 `[A] 西瓜重炮 × 追猎者`（面板出现 `RUN 1.`）。
   停留约 6–10 秒让真实物理跑出过程（起始有远程交战段）。
2. 点 **`Gate 下一步`** → 第 2 步 `[B] 西瓜重炮 × 追猎者` → 面板出现 **`BLK 2.`**，
   Lab 停在 idle 且**不会 Start**（这就是「Arena B 未实现」的如实呈现，录进去即可）。
3. 点 **`Gate 下一步`** → 第 3 步 `[A] 香蕉冲锋锤 × 远程炮台` → `RUN 3.`，停留 6–10 秒
   （观察推进接敌 / 撞击 / 后坐）。
4. 点 **`Gate 下一步`** → 第 4 步 `[B] 香蕉冲锋锤 × 远程炮台` → `BLK 4.`。
5. 点 **`Gate 下一步`** → 第 5 步 `[A] 香蕉冲锋锤 × 3 轻敌人` → `RUN 5.`，停留 6–10 秒
   （观察三敌独立 / 敌↔敌真实碰撞 / 不串伤害）。
6. 点 **`Gate 下一步`** → 第 6 步 `[B] 香蕉冲锋锤 × 3 轻敌人` → `BLK 6.`。
   此时面板显示 `已推进 6/6`。
7. 点 **`Reset`** → 回默认（Arena A / 西瓜重炮 / 追猎者），门禁游标归零、无任何残留。

**每一步都请把门禁面板一起录进去** —— 面板上会同时显示
`切场零残留：[] （干净）`，这就是「每次切场/Reset 完全清理 HP / body / projectile / contact state /
AI / movement state / arena state / enemy instances」的可视证据。

> 若要单独展示某一组合，也可以直接点 `Arena / Loadout / Encounter` + `Start` 手动组合；
> 6 步固定顺序只是**建议的主线**，不是唯一可达路径。
