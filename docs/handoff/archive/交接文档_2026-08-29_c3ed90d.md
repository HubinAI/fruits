## 3. 当前微信渲染管线状态（本轮核心成果，必须吃透）

### 3.1 真根因（比 C3 更彻底的一层）

微信首画布默认 `canvas.width = windowWidth`（**逻辑**），而链路按「canvas.width = 物理 backing」假设；且 `WechatViewport` 把 backing 当 `surface.width`（renderer 的 fit 域），绘制时又 `setTransform(dpr)` →
**fit 域与绘制域双重缩放** → 真机/模拟器全局放大 + 裁切。C3（46d6ea1）的 backing 定版只是必要不充分。

### 3.2 修复要点（c3ed90d）

1. `wechat/game.ts`：在 surface/UI/Input 创建**前**，按 `windowWidth × pixelRatio` 定版 screen + ui 两块 Canvas backing。
2. `WechatViewport.surface.width/height = canvas.backing ÷ dpr`（= 逻辑窗口；契约见 `canvasSurface.ts`）。
3. `renderer.ts` 新增 `viewToLogical`（恒 1）统一所有 `vk = surface ? viewDpr : 1` 与 `÷viewDpr` 域对齐点（isCompact / getVehicleScreenRects / groundScreenY / lastGroundScreenYLogical / fit insets / framing）——**DPR 只在最终绘制应用一次**。
4. `wx.onWindowResize`（如存在）同步两画布 backing + `runtime.doResize()` 重取景；surface 实时读 canvas，无旧尺寸残留。
5. 新增 `[WX-SURF]` boot + 首帧全链诊断日志（`__WX_DEBUG__` 门控，普通包零开销）。

### 3.3 测试基建升级（本 Queue 的大头）

- FakeCanvas 支持运行时 resize（ink 随 backing 重分配）；FakeCtx2D 新增 `drawOps`（device bbox 几何验收）、`affine`（translate/rotate/scale/transform）、path 跟踪（arc 4 轴向点防 45° 退化）、`textAlign/textBaseline` 对齐、`fastRaster`（面积记账控时）、`resetInk`。
- **`fontSize()` 必须匹配 `px` 后缀**（否则抓到字重 700 使 text bbox 虚大）——写新测试时沿用。
- 新门禁：
  - `wechatSurfaceTransform.test.ts`：4 环境（844×390 / 2048×941 / 2532×1170 / 2796×1290 × DPR 1/2/3 × 非整数 contain）backing 定版，先红后绿（禁定版后红：`expected 1024 to be 2048`）。

## 5. 项目纪律与工具层坑（每条都是血泪经验，新会话必读）

### 5.1 运行/验证硬规则
- **vitest 必须带 `--pool=vmThreads`**（或 vmForks）：默认 forks/threads 池在本环境全部报 `Cannot read properties of undefined (reading 'config')`（vitest 4.1.10 / Node 24 / Windows 双实例故障），是**环境问题非代码问题**，误报"测试失败"。
- **三路 SHA 一致性**：local HEAD / remote（ls-remote 实测）/ server badge 三路交叉核对。Dev Server 未重启时录制内容可能滞后于最新 commit（**stale-recording 陷阱**），先确认服务实际运行版本再下结论。
- **e2e 硬约束**：禁止 fake-viewport / fake-mouse / hitArea / `__h` / `__probe` / getImageData 捷径绕过 e2e；必须真实像素 + 实际鼠标点击。禁止用 Web 构建冒充 WeChat。
- **三层验收**：技术正确（tests/build）→ 方案落地（正式 Runtime）→ 实际体验成立（1x 速度 + Debug 关 + 玩家能感知/理解/归因/决策）。**开发完成 ≠ 体验通过 ≠ 进入正式主线**；自动化门禁通过 ≠ 真机体验确认。
- **Queue 纪律**：每条 Queue 完成后 stop-and-wait：单 commit + push，停下等待真机回执再开下一条；禁止顺手扩展范围。investigation queue 与 fix queue 严格区分，前者禁 commit/push/deploy。每条 Queue 开始前声明 frozen baseline invariants（必不动项）。

### 5.2 环境工具层坑（Windows + 中文路径）
- **git status 把 `planck` 显示成 `plank`（无 c）**：中文路径显示伪影，真实文件名始终是 `planck`。用 `ls <dir>/` 拿真实拼写，勿信 status 显示名。
- **Git Bash 对中文目录相对/绝对路径不稳**：git 命令用裸相对路径（`git diff HEAD -- <file>`）几乎都稳；Read 工具对绝对中文路径偶发 "Not found"，Bash `cat` 兜底。
- **git ref 写入不可靠（重要）**：`git commit` 后分支 ref 常不落盘；`git update-ref` / `git branch -f` 也静默失败。**可靠恢复路径**：`mkdir -p .git/refs/heads/<branch> && printf '%s\n' <full-sha> > .git/refs/heads/<branch>`；commit 后必须立刻 `git log` 验证 ref 落盘，未落盘用 fsck/cat-file 确认对象完整后手动写 ref 再 push。
- git 身份：本仓库 `xiaoyue <xiaoyue@local>`（新会话需重新设置）。push 走 SSH（`git@github.com:HubinAI/fruits.git`），SSH 通道免密可用（ls-remote 已实测）。
- 微信 iOS 真机调试：**必读** `.workbuddy/memory/F-WX-IOS-REALDEVICE-DEBUG-PLAYBOOK.md`（坐标域先标注 / DPR 单次应用 / 内部 rect≠最终像素 / Web≠微信≠真机 / 三层状态分开表述 / 先红后绿+模拟器+真机录屏 / 禁补偿掩盖）。

### 5.3 冲突处理
最新任务与本基线核心定位（极简策略 + 事前组装 + 自动物理战斗）冲突时：**不自行默默实现冲突方案**，先指出「冲突点 + 体验/架构后果 + 最小建议修正」。方案漂移红线（出现即主动提醒）：复杂职业 AI / 自动瞄准 / 自动拉距 / 大量隐藏 Buff / Body 免费攻击 / MaxWeight 硬限制 / 动画保证命中 / 高品质全维度碾压 等。
