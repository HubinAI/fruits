# FRUITS-ADVENTURE-UX-CONTINUITY-R1｜一屏式冒险整体重构基线

## 目标与约束
- 用户已经两次明确否定冒险原型的**实际完成度**：战斗与事件完全分屏、割裂、反复「继续」，不是镜头抖动或字体微调问题。不要用技术测试通过反驳体验。
- 唯一主要目标：一次冒险是一段**持续推进的旅程**，战斗、事件、奖励、强化共享同一屏幕结构。玩家的下一次点击应具有明确行动意义。
- 只在冒险实验入口优化 UI/交互；冻结正式首页/车库/物理/碰撞/伤害、F1-F6 的正确战斗能力。**允许修改冒险展示和非决策节点的推进交互**，必须保持实际随机、经济与结果等价。
- 不自动接入正式主线。第三方拆包素材只供内部原型，不提交到 Git，也不得用于公开发布包。

## R1 确定的页面骨架（390x844 竖屏）
- 顶部约 0-60：现有 DAY n/26 进度 + 实时耐久；不要虚构没有的 EXP/攻防系统。可用现有强化图标做紧凑标识。
- 中上约 60-430：**同一冒险舞台**；战斗、休息、探索、胜利都留在此场景，战车/敌人按状态出现/停留。绝不默认改成王座厅/宝箱专页。若选择合适的 P0 背景，要全流程统一、不能来回换气质；保持真实战车物理渲染。
- 中间约 430-490：稳定状态条（耐久变化/战斗结果/当日小标题）；不叠大段 Debug、不重复显示满屏战报。
- 中下约 490-730：**固定叙事/事件区**，1-2 张高对比浅色事件记录卡；事件标题、效果增减、战斗结果依时间依次出现，场景不跳走。需要二选一时可直接把卡片替换为两张可点击选项。
- 底部约 730-844：固定主操作位。真的需要下一步才出现「下一天/出发/领取」；战斗自动进行时不铺一个假的可点击「战斗中」按钮；没有动作不显示假 CTA。
- 必要多项技能选择时允许**覆盖在同一个舞台上**的暗背景弹层，结束后返回原位置；不得跳到新的独立场景。
- 这里的像素是布局意图，按视觉合理调整；F1/F6 冒险舞台裁切必须随区域变化等比适配，不能重新引入非等比/抖动。

## 交互重构
- 保留「战斗→真实胜负/伤害→经济变化→事件/选择→下一天/下一场」顺序和数据。
- 合并纯信息过场：BANNER/IDLE/RESULT/EVENT_DONE 等不应每步另开整页等待「继续」。信息写入叙事区或短结果横幅；在需要玩家决策时停留。
- 如宝箱需要玩家主动开启，可保留一次「打开」操作，但开箱后结果**直接填到同一屏的叙事区**，不再要求多次「继续」。
- 选择卡点击后立即应用真实效果与轻量反馈；后续只在下一天/新战斗真正需要玩家发起时保留一次主操作。
- 不允许出现「事件选完→领奖页继续→叙事页继续→进入战斗再继续」四连重复操作。
- 要能区分点击类型：主操作（仅实际推进）、选择项、无意义确认；旧诊断 seed scan-4 约 26 次主操作/8 次选择，是待改善基线，不是游戏必须保留的流程。
- 保障输入禁重、快速点击、多个连续事件/BUILD、失败或终局转场不跳节点、结果不重复领取；正式/冒险存档隔离。

## 实施边界与产品预验收闸门
- 先搭一套真实可玩的**统一主屏骨架**，再把现有流程接入；不是简单换按钮图片/字体。若状态机需要修改，仅限冒险展示/推进，必须验证经济效果完全等价。
- 交付**正常速度**同一段流程证据：战斗中→击败→收益→事件选择→成长→再次战斗，完整经过 UI 的核心形态；WorkBuddy 可自动采浏览器视频/连续关键帧，不能要求真人代录。
- 在 390x844 下需由 WorkBuddy 自己检查：舞台一套视觉语言、浅色文本区信息读得清、没有不必要页面切换、不卡屏、按钮不假点，素材不缺失/不变形。
- 工程门控：tsc、定向 vitest、完整浏览器 E2E（胜/败/新种子）、F1 等比/F2 HP/F3 技能/F5 修复/F6 镜头稳定性不退化。
- 最终 GPT 先对**真实画面与视频**做视觉预验收，未通过不得再交给用户体验；用户只判断最终爽不爽、顺不顺、是否愿意下一局。
- 产品体验成功标准：用户无需解释就知道当前在经历什么、操作一次带来什么；战斗与事件是**同一段旅程**，而不是拆成三套页面。
