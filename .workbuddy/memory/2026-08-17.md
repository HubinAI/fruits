## Queue F-01｜Canonical Physics Foundation（feature/foundation-02-canonical，commit d9be265）

建立唯一 Canonical Foundation，统一 dev 与各 Content Queue 的分叉物理基线。

### 完成的修复（根因 + 代码证据）

1. **gravity.scale 统一 0.0001**（adapter.ts）
   - 根因：Matter Verlet 积分 `velocity += (force/mass)*deltaTime²`，FIXED_DT²≈277.8 放大 gravity.scale。
   - 0.01 时重力项 2.78px/step；且 Matter 碰撞求解器只改 positionPrev、不回写 body.velocity，
     导致静止/驱动车 body.velocity.y 单调累积到终速 ~278（实测 600 步后 vy≈284）。
   - 0.0001 → 每步 0.0278px，vy 收敛到 ~1.6（<5），车仍正常接地驱动（驱动前进距离几乎不变）。

2. **setMeta 传播到 compound sub-part**（adapter.ts）
   - Matter 碰撞事件 pair.bodyA/bodyB 是 sub-part（Detector 从 parts[1..] 遍历，parts[0]=parent 被跳过）。
   - sub-part 不继承 parent plugin → 此前车身 sub-part 读不到 Owner → Impact/Direct Weapon Damage 全失效。
   - 修复：setMeta 同步 meta 到所有 sub-part（单 body parts===[self] 幂等）。

3. **固定步进重构**（battleOrchestrator.ts + adapter.ts step onBeforeStep 回调）
   - 旧：先 world.step 后 driveVehicle → 驱动只每「帧」施加一次，30FPS 下驱动减半。
   - 新：Drive 在每个 FIXED_DT 的 Engine.update 之前执行（onBeforeStep）；战斗时间按 steps*FIXED_DT 推进。
   - 验证：旧逻辑下 FPS 一致性测试失败（30vs60 差 25.9px），新逻辑通过（≤2px）。

4. **重标定 Scenario B**：偏心碰撞阈值 0.02→0.008（gravity 标定后实测 ~0.010 rad/step，对齐 Queue 02/03）。

### 测试结果
- tsc 0 错误；vitest 33 通过（28 原有 + 5 新增 targeted regression）；vite build 成功。
- 新增 tests/foundationCanonical.test.ts：FPS 一致性 / vy 不累积 / sub-part meta 传播 / Baseline 无抬头。
