- **可视化**：renderer 画 projectile；debugOverlay 加「炮口方向」开关（muzzleDirection）。

### 暴露的 Foundation 问题（已修，重要）

**gravity.scale 标定错误**。根因：Matter 用 Verlet 积分 `velocity += (force/mass) * deltaTime²`，其中 deltaTime²=277.8（ms²），因此 gravity.scale 会被放大 277.8 倍成为实际加速度（px/step²）。

- 01A 曾把 gravity.scale 调到 0.01（为 setAngularVelocity 摩擦驱动），实际产生 2.778 px/step² 重力 → Projectile 约 5 步就下坠撞地，弹道完全失真。
- 01B 改成 applyForce 水平驱动后，车驱动已不依赖重力（实测 gravity 0.00005~0.01 车前进距离几乎不变 214~227px）。
- **修复**：gravity.scale 0.01 → 0.0001，projectileSpeed 8 → 18。结果：车仍正常接地驱动（且姿态更稳 maxAngle 0.3°），Projectile 获得合理平射弹道（飞 800px 下坠 ~27px）。

### 关键认知（后续必读）
1. **Matter 力单位**：任何 `applyForce(F)` 的速度增量 = `F/mass × 277.8`（px/step）。标定 force 时要乘这个因子。
2. **初始冷却**：weaponCooldowns 初始化为 cooldown（出生后等一个冷却周期开火），不是 0。
3. **低 gravity 下软约束让车身回平更快**：轮径差倾角（Scenario C / P3）在 gravity 0.0001 下 settle 后 ±6.2°，运行 90 步后 noseUp 稳定 -5.5°、noseDown 6.4°（方向保留，可接受）。Scenario B 偏心碰撞角速度从 0.027 降到 0.010（阈值调 0.008）。

### 环境问题（重要）
- **Shell 通道（sandbox runner）反复崩溃**：rm / git commit 等命令 exit 1 无输出（进程被杀死）。git commit 需要 `dangerouslyDisableSandbox: true` 才能写 .git 文件成功。
- **git ref 更新异常**：feature 分支 commit 时，commit 对象创建成功但 ref 文件（.git/refs/heads/feature/queue-02-cannon）更新失败（悬空 commit）。需手动 `mkdir -p .git/refs/heads/feature && printf '<hash>\n' > ref` 修复。这与用户记忆里「sandbox runner 层崩溃」的诊断一致。

## Queue 03：Heavy Hammer / Swing Weapon（feature/queue-03-hammer）

### 交付内容
- **Hammer 武器**（content.ts）：behavior='hammer'，参数 cooldown/armLength/headRadius/headMass/armMass/swingSpeed/damage。
- **挥击装配**（vehicleAssembly.ts）：hammer 用 compound（锤头 circle + 杆 box）+ Revolute Joint 挂 hardpoint；挂点对齐 hardpoint（非 COM）；joint damping 0.05、stiffness 默认 0.5。
- **挥击驱动**（weaponHammer.ts）：冷却到点施加角速度冲量，`part.swinging` 记录挥击状态（供命中判定）。
- **命中判定**（contactRouter.ts）：hammer 用 swinging 状态（非相对速度/角速度），ram 仍用相对速度。
- **Lab**：H1（命中）/ H2（偏心）/ H3（挥空）三个 Scenario + hammerVehicle Preset。

### 暴露的 Foundation 问题（已修，重要）
1. **Matter compound sub-part 不继承 parent 的 plugin**：碰撞事件里 pair.bodyA/bodyB 是 sub-part（plugin 为空），导致 Contact Router 读不到 Owner meta。修复：createCompound 里把 opts.meta 同步到所有 sub-parts。
2. **gravity.scale 0.01 遗留**（与 Queue 02 同源）：hammer head 受重力快速下垂，挥击轨迹失真。修复 0.01 → 0.0001（从 Queue 02 同步）。
3. **revolute joint stiffness 0.9 数值爆炸**：arm 被甩飞（dist 涨到 ~200）。稳定区间 0.5~0.7（dist=臂长）。
4. **joint damping 0.2 吃掉挥击角速度**：0.35 → 0.11 → 0.01 一帧衰减。降到 0.05。

### 关键认知（Matter 软约束的深层限制，后续必读）
- **Matter 的 constraint 是软弹簧**，对「旋转臂主动挥击」的角速度每步衰减 ~70%（setAngularVelocity 0.35 → world.step 后 0.11）。这是引擎固有限制，不是代码 bug。
- 后果：hammer head 挥击速度只有 3~5 px/step（预期 15~23），命中时 av 接近 0，无法用「相对速度/角速度」判定有效接触。
- 对策：用「挥击状态标志」`part.swinging`（开火后 1200ms 内算挥击中）判定命中，而非角速度阈值。
- setAngularVelocity 在 Matter 的 Verlet 积分下有效（设置 anglePrev 产生角速度），但 constraint 求解器会衰减它。
