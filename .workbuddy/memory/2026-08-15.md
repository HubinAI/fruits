### 关键坑（务必记住，后续迭代会用到）
1. **Matter.Body.create({parts}) 会按 parts 的 COM 重算 position**，覆盖传入的 position → 必须 `Body.setPosition` 显式设置。
2. **Matter 默认 gravity.scale=0.001 太小**，轮子摩擦牵引力不足 → 提到 0.01。
3. **Matter 的 Coulomb 摩擦对「纯滚动」的法向力（源于穿透）在静态平衡趋近 0**，单靠 setAngularVelocity 无法驱动整车 → 接地轮额外施加 applyForce 真实水平牵引力（driveForce=0.005，非假移动）。
4. **revolution joint stiffness=1 会导致落地翻车** → 用 Matter 默认 stiffness=0.7 + damping=0.1。
5. **Arena Closing 刺墙若用巨大质量动态体（mass=100000）会破坏世界稳定性** → 初始 setStatic(true)，Closing 阶段再激活。
6. **多辆车共享 world 时，Matter 的 pair id 递增导致浮点非确定性**，落地姿态会分叉（翻车 vs 稳定）——这是 Matter 固有限制，Scenario C 的落地稳定性属第三层体验验收，留待后续调参。

## 01A 稳定性返修（P0，commit 3b22d44）

**问题**：标准双轮车无碰撞时大幅抬头（wheelie），接近竖起；Scenario C Reset 落地姿态不稳。

**无碰撞抬头真实根因（两层）**：
1. `setAngularVelocity` 强制 wheel 角速度——Matter 没有真正 revolute joint，length=0 高刚度约束会被强制角速度顶起后轴（StackOverflow 官方确认此现象）。
2. 固定 driveForce 持续施加 = 持续加速 = 持续抬头（真实物理：匀速时牵引力≈0，车身回正）。

**修复点**：
- movement.ts：去掉 setAngularVelocity，改为 `applyForce` 施加在 wheel 顶部（y-radius），力朝前进方向（同时产生前进牵引 + 正向滚动力矩）；加「目标速度控制」（TARGET_SPEED=1.5 px/step，接近目标速度后驱动力按比例衰减）。
- adapter.ts：revolute joint stiffness 0.7 → 0.4（loose axle，稳定不抬头）。

**是否改全局物理参数**：是，改 constraint stiffness（0.7→0.4）。原因：Matter 无真正 revolute，高刚度会被顶起后轴；0.4 是「驱动稳定」与「轮径倾角」的平衡点，属正常物理标定（非掩盖 Runtime 问题）。

**权衡/残留风险**：stiffness 0.4 下「轮径改变倾角」幅度被软悬挂部分削弱（倾角差 ~1°，方向保留但不如刚度 1 时明显）；noseUp 落地仍偶发翻车（Matter 多体浮点非确定性，多数次稳定）。

**回归**：27/27 测试通过（新增 baselineDrive.test.ts 3 个：Baseline 5 秒不抬头 / 腾空零牵引 / Scenario C Reset 稳定）；tsc 0 错误；vite build 通过。

## 01B Wheel Posture 恢复 + Lab 比例校准 + GitHub Push（本 commit）

**三大根因定位（关键认知，后续必读）**：
1. **Reset 随机翻车的真根因 = Matter 全局 ID 计数器 `Common._nextId`**。每次新建 World，body id 全局递增 → broadphase/solver 迭代顺序不同 → 浮点分叉 → 混沌翻车。修复：PhysWorld 构造时重置 `Common._nextId = 0`。
2. **「朝左 = 180° 旋转」是概念错误**。rotate(硬点, π) 会把轮子翻到车顶（y 也翻转）。正确是「镜像 X、保持 Y」（轮子永远朝下）。已把 spawn 的 `angle` 换成 `facing: 1|-1`，硬点/碰撞轮廓按镜像变换。
3. **沉降坐标方向搞反**：Matter y 轴向下，车底 = 最大 y，但旧 settle 用 `bounds.min.y`（车顶）→ 整车下沉 77px。修复：用顶点求最大 y 再平移。

**轮径姿态的处理（重要权衡）**：Matter 的 Constraint 本质是软弹簧（即使 stiffness=1），前轮（轻）会「浮空」导致车身回平，轮径差无法动态产生稳定倾角；升高 stiffness/gravity/迭代次数都试过，要么回平要么爆炸。最终方案 = **「刚性静止姿态出生」**：按几何 `θ = atan(Δr/轴距)` 摆正车身+轮子再贴地（这是正确的初始物理条件，非伪造），出生即正确倾角。实测：noseDown 出生 +6.23°→稳定 ~+2.6°，noseUp 出生 -6.29°→稳定 ~-7.3°，方向相反、差 ~10°、无翻车。

**本轮改动**：
- adapter.ts：revolute joint stiffness 0.5 / damping 0.2；PhysWorld 重置 `_nextId`。
- vehicleAssembly.ts：facing 镜像装配；`settleVehicleToRestPose`（几何倾角出生）+ `settleVehicleToGround`（用最大 y 求车底）。
- battleOrchestrator.ts：先建 Arena 再建车；`settleToGround` 配置（D-air 设 false）；drive 用 vehicle.facing。
- content.ts：3 种测试 Body（wedgeBody 低前鼻 / boxBody 厚实 / tallBody 高身），Body 成为主体。
- presets.ts：noseDown/noseUp 改平衡（去掉前重 ramHead，纯演示轮径）。
- scenarios.ts：angle→facing；D-air settleToGround:false。
- renderer.ts：VIEW_ZOOM=1.8 镜头放大（Camera 与 Physics 尺度分离）。
- 测试：27/27 通过（baselineDrive 改为验证「几何倾角出生 + 无翻车」，Scenario B 阈值 0.1→0.03 适配更大车身）。

**遗留风险（如实标注）**：软悬挂仍会部分吸收轮径倾角（noseDown 稳定态 ~2.6° 偏弱、noseUp ~7.3°），且幅度受 JIT 浮点影响；这是 Matter 软约束固有限制，若要拉满需换引擎或改 rigid 装配（本轮不扩 Content 未做）。
