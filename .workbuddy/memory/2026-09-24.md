### 1. ★ 全量门禁抓出一个**真实丢档 bug**（本轮最值钱的一件事）

第一次跑全量门禁时，**不是**本轮的定向 E2E，而是**别人**的 `e2e:product-reward`
拦下了 3 条（`K8` / `H2` / `H3`），磁盘读数 `equipped=cannon ★1 · ★1=4 ★2=0`：

```
新账号首入（还没领过奖）→ 自己打一局 → 领奖 → 5/5 → 合成 ★2 → 回首页
⇒ 玩家**自己刚合出来的** ★2 被当成「上一轮的产物」清掉，★1 还被倒补回 4
```

**根因**：`planR2Reseed` 的五条判据读的是**当下库存**，而库存**会被玩家自己改变**
⇒ 我把「首入判定」写成了「每次挂载都判」的连续判定。判据 ③（领奖账本非空）我当成了
「产品账号恒真」，**实际它在玩家第一次领奖那一刻才由假变真**。

**修法**：`R2ReseedPlan` 加 `decided`（= 「新版本首入的判定结论是否已做出」，与
`R2OnboardingPlan.needsMark` 同形同纪律）⇒ 调用方 `if (reseed.decided) markR2Reseed();`。
四个「一个字节都不动」的出口**一律落标记**；唯一例外 = 可重试的 `equip-failed`。
**这是正确性要求不是优化**：判据含单调变化的库存读数，`already-marked` 是唯一能钉成一次性的东西。

新增防线：单测 `VR-06` / `VR-06b`（逐字复刻该路径）/ `VR-08..VR-11`、源码守卫 `VR-15`、
E2E `R5a/R5b/R5c`（真实浏览器：首入标记落盘 → 玩家自己合成 ★2 → **零写入**）。
