## 1. `PRODUCT-LOOP-R7-WEAPON-BASIC-BUILD-CONTENT`（7 件武器的通用基础成长）

**起点 `cd4fc5e`。** Queue 一句话：让 7 件 Full Run Weapon 都至少拥有**最小可用**的局内 Build
成长（不是正式长期 BD 系统），严格使用 Q1 Capability Matrix，Cannon 既有 5 项内容**全部冻结**。

### 1.1 做了什么（3 条判断 + 1 个新接缝）

| # | 判断 | 依据 |
|---|---|---|
| ① | **伤害是唯一真共通维度** | `behaviorParams` 里「顶层 + 数值 + 键名含 `damage`」的**唯一**键，7/7 各恰一个 |
| ② | **节奏键不是同一个字段 ⇒ 不强行统一** | 5 件 `cooldownMs`（1000/600/1800/1100/1300）· `rammer.restSteps`=24（在 canonical）· `hammer.windupPauseSteps`=20（**只在行为默认**） |
| ③ | 两条成长 = Queue 指定的优先级 ①② | `damageUp` 伤害提升 ×1.25 · `rateUp` 攻击加快 ×0.75（下限 1） |

**唯一新接缝** = `RunPageContext.baseWeaponDefId`（**可选，缺省 `'cannon'`**）⇒ 既有全部调用点逐字节不变；
产品路径由 `runPageScene.runPageContext()` 从 `runLoadoutCompatOfDraft(draft).baseWeaponDefId` 注入，
与运行时 overlay 注入、Run 创建资格**同一函数链**（三处不可能漂移）。

### 1.2 防污染的**结构性**做法（不是靠断言兜）
- `RunBuildId = RunModifierId | GenericGrowthId` **并集** ⇒ 通用成长**不进** Cannon 的 id 闭集 ⇒
  `RUN_MODIFIERS` / `RUN_BUILD_MODIFIERS` / `RUN_LAYER2_POOLS` / `RUN_ALL_MODIFIER_IDS` /
  `RUN_CHOICE_OPTIONS` / `RUN_MODIFIER_OVERLAY` **一字未动**。
- `weaponOverlayMods` 改**两条互斥支路**：cannon ⇒ Cannon overlay 项（显式排除通用成长）；
  非 cannon / `null` ⇒ **只放行通用成长**。
- `composeRunWeaponDef` 的通用成长支路**只浅合并 `behaviorParams`** —— 支路里**没有代码可以改写
  `behavior`** ⇒ 「hammer 选成长变成 cannon」在结构上不可能。

### 1.3 真实 Runtime 实测（`tests/productRunWeaponBasicBuildR7.test.ts`，11 条 GR）
逐件**真跑战斗**、读 `playerWeaponHitSummary()` 的真实 `damage` 事件：

| 武器 | behavior | 零 Build 逐发 | 带 `damageUp` 逐发 |
|---|---|---|---|
| `cannon` | cannon | 120（玩家基线） | **120（冻结，一个数字都没变）** |
| `flamethrower` | flamethrower | 8 | 10 |
| `hammer` | **hammer** | 90 | 113 |
| `laser` | laser | 160 | 200 |
| `machineGun` | machineGun | 20 | 25 |
| `rammer` | rammer | 70 | 88 |
| `shotgun` | shotgun | 30 | 38 |

`GR-06b`：机枪带 `rateUp` ⇒ **下一轮 burst 的弹丸出生步号真的更早**（不是读配置），且逐发伤害不变。
`GR-08`：同一局内三段逐发伤害 `[20] → [25]`（选完 `damageUp` 后**下一段**真的变大）。

### 1.4 踩到的两件事（都固化进 REF §19）

1. **`buildPriorCompletedRun` 的快进路线是写死的 Cannon id** ⇒ 非 cannon 局
   （`EL-22` 刻意传 `laser`）里那些 id 一项都不在池中 ⇒ 快进**停在 `CHOICE`**、拿不到 `COMPLETE`
   （全量 vitest 唯一 1 红）。处置：Cannon 族继续走声明路线；**通用族不由该文件命名任何 id**
   （平铺池没有层级语义），按池自己的声明顺序取首项；两支路都保留「取不到就 break」。
   ⚠️ 刻意**不**在该文件写死通用 id —— 那里有 `NR-03` 源码守卫禁止未注册的强化 id 字面量
   （第一版按「声明路线表」写死 `['damageUp','rateUp']` 时**正好撞红**，遂改成池驱动）。
2. **写测试的两个坑**：① 走查循环顶部漏 `COMPLETE || FAILED` 的 `break` ⇒ `pressRunAction`
   在终态是「开新 Run」（`runStartsNewRun`），实测一局接一局跑出 **67 段**战斗；
   ② `WEAPON_SLOT = 'frontMass'` 是字面量类型 ⇒ 对象字面量里 `frontMass:` 与 `[WEAPON_SLOT]:`
   同时出现 = `TS1117`（改用 `slot: string = WEAPON_SLOT` 形参，与既有 R7-BATCH 夹具同款）。
   另：`GR-03` 第一版把 cannon 也断言成「伤害必须变大」⇒ 当场红 —— 这**恰好证明** Cannon 冻结生效，
   遂改成 cannon 分支断言**零变化**。

### 1.5 负控制（已做）

## 2. PRODUCT-LOOP-R7-WEAPON-ENCOUNTER-MATRIX（test-only，`4f2bbf9` → `2a5021a`）

（12 条 `MX-01`…`MX-12`，+672 行）。冻结 8 目录 `git diff --stat` 全空 ·
`content.ts` / `contactRouter.ts` 逐字节一致 · `src/product/` 零 diff。**未改任何战斗参数。**

### 2.2 口径（关键：与 `Q3-07` 是**两个不同问题**）
单场隔离 = `onlyDraft`（车上只这一件）+ 满耐久 + **零 Build** + `playerBaseline:true`；
固定窗口 = **前 600 步**（= `DEFAULT_ARENA_CONFIG.phases.activeMs` / `FRAME_MS`，锚既有常量）；
上限 4000 步。`Q3-07` 是**三段链**（混入跨段耐久累积）⇒ 两表不能互相代入。

### 2.3 结果（21 格全冻结，`MX-06`）
- **21/21 全部进正式终态**（无「无限拖延」）；`endReason` **全部 `'hp'`**（无一走到 `arenaEnd`）。
- **`RangedTurret` 列 = 7/7 全部落败**，但**分成三组**（这是本 Queue 的核心产出）：
  1. **真·够不着**：`rammer`（`minGap = +7 > 0`，全程从未接触）；
  2. **接触过却没登记武器命中**：`hammer`（`minGap = −23` 深度重叠、有 `impact`、武器命中 0）；
  3. **够得着但打不过**：`cannon`(1/120) · `flamethrower`(66/528) · `laser`(4/640) ·
     `machineGun`(47/940，**最接近**：敌剩 159.8) · `shotgun`(20/600)。
- 近身两段（Proto/Rusher + Chaser）7/7 都能打出真实伤害；`laser` 两段都输（DPS 不够）。
- `rammer|Chaser` = 双方归零 ⇒ **tiebreak 判 A**（如实记，不是「赢」的通词）。
- 附加行：产品默认车 vs `RangedTurret` = **2 命中/240，全部来自 `cannon`**（`top` 槽零贡献）。

### 2.4 三个坑（都写进 REF §20e）
1. **源码守卫「自指陷阱」第 3 次**：`MX-12` 的禁用词表自己会被 `src.includes(token)` 匹配 ⇒
   必须**拼接构造**（`'.' + 'hp = '`）。
2. **哨兵值与合法值撞车**：`gapAtWindow` 初值 `-1`，但间距合法可为负（−23）⇒ 改 `null`。
3. **期望值别抄隔壁行**：`MX-10` 默认车 vs `RangedTurret` 我第一版抄了「只装 cannon」那行
   （1/120），实测是 **2/240** —— 差点把一个抄写错误误读成「物理变了」。
   另：`vitest --reporter=basic` 在 vitest 4 **不存在**（`ERR_LOAD_URL`，EXIT=1 但无失败）。

### 2.5 ⚠️ 方法论收获
