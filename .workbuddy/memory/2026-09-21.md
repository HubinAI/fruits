## 本轮队列：结算 CTA → 领奖/保存 → 清理 Run → 返回首页 的延迟

真人录屏 P0：RUN COMPLETE 结算页正常显示奖励卡，但点底部「完成本次冒险」后
**约 5 秒完全静止在同一画面**，随后才跳回首页。

### 结论（一句话）

**这 5 秒不在代码里，是一个「画着却点不动」的死按钮造成的观感。**
真实链路墙钟：点击→导航发起 **4.7 ms**、导航→首页可见 **52 ms**、**0 longtask**。

### 根因（file:line）

- `src/lab/portraitBattleLab/runPage.ts` `drawActionButton()`（`:1929` 起）只覆盖两支守卫：
  「验证终点态无出口」「FAILED 无回程地址」，**漏掉第三支** —— 有候选卡的 `COMPLETE`。
  此时 `actionEnabledNow()`（`:1306`，`:1307` 有候选即 `false`）为 `false`，
  但函数继续往下画，用禁用态色 `actionFillOff/actionBtnOff` 画出一条「完成本次冒险」。
- `onPointerDown`（`:1132`–`:1150`）：有候选卡时**任何非卡片点击直接 `return;`**（`:1149`）
  ⇒ 底栏那条按钮的命中路径**不可达**。玩家点它 = 零反馈 = 被读成卡死。
- 玩家最终点到**真卡**（`rewardChoiceRects[0]` = `{x:14,y:302,w:362,h:68}`）时，导航是瞬时的。

# PRODUCT-LOOP-P0-SETTLEMENT-SINGLE-CTA-AND-AUDIO-LIFECYCLE（同日第二轮，真人验收驱动）

## 一、两个根因（都是"结构性"的，不是调参）

1. **没有主 CTA**：上一轮把「有候选卡时底栏按钮不可用」当成修复，结果出口只剩卡片。
   本轮产品前提已变（COMPLETE 奖励**固定 cannon ★1 ×1**）⇒ 反转契约：**卡片纯展示，底栏是唯一入口**。
2. **战斗音不断**：`RunBattleView.dispose()` 只调 `presentation.stop()`，而它**只解绑事件订阅、
   一个音源都不停**；终局对手 `BananaRodLaser` 死在**蓄能途中** ⇒ 那声**循环蓄能音源**一直响。
   真凶 = `SfxAudioService.stopBattleAudio()` **在 Lab 里从未被调用**。
   ⇒ `RunBattleView` 自持 `SfxAudioService`，终态那一帧就停（不等 dispose），两处复用同一幂等入口。

## 二、C9 排查链（四轮，全部靠"量"收敛 —— 这段是本轮最值钱的经验）

写「连点 3 次不重复领取」的取证时，`claimStarts` 一直读成 `n/a`。逐轮排除：

| 轮 | 猜测 | 实测 | 结论 |
|---|---|---|---|
| 1 | 连点把 2 帧窗口耗光 | `first` 读到 `claiming=true/starts=1`，`afterExtra` 为 `n/a` | 读**第二次**失败，不是点击 |
| 2 | 裸 CDP `Runtime.evaluate` 能绕开"等新文档" | `elapsedMs=1608`、`hasRunPage=false` | ❌ 裸 CDP **也**等新文档 |
| 3 | 会话创建开销吃掉窗口 | 连点**只花 5ms**（同批发出） | ❌ 连点不是嫌疑人 |
| 4 | 钉住上下文的读应当立刻返回 | `elapsedMs=1577` + `Cannot find context with specified id` | 挂起**反而**把读毁掉 |

**追根因时挖出一个既有 E2E 假绿**：`page.waitForURL(/home\.html/)` 会**当场匹配 Run 页自己的地址**
—— 它的查询串里带 `home=.%2Fhome.html` 这个**参数取值**，里面天然含 `home.html` 子串。
于是它「先看当前 URL」这一步当场成立、**立即返回、根本没等导航**（实测 `navMs=23ms`；
挂起/路由也因此被提前撤销 ⇒ `路由进入 0 次`、`挂起生效 0 次`）。
**旧版本看起来正常纯属巧合**：那一次窗口探针读数要 1608ms，把 `navMs` 顺带撑到 1571ms，正好落进上界内。

最终形态：**不人为挂起导航**（窗口本来就是天然的「按下 → 两帧」≈33ms），
读走**按下前**就 `Runtime.enable` 抓好的**旧文档 `contextId`**，4 次真实鼠标点击**同批发出**，
**只读一次**（一次读数同时证"同帧反馈"与"连点不重复"）。
`navMsNet === navMs`，实测 **46~51ms**（上界 4000ms）。

⚠️ 另外两条会让人白干的坑：
- **JS 块注释里不许出现 `*` 紧跟 `/`** —— `page.route('**/home.html*')` 这种字面量会把注释**提前闭合**，
  实测让 `node --check` 直接报错（与 MEMORY §2 那条 HTML 注释陷阱同类）。
- Playwright 里**后注册的路由优先** ⇒ 用 `**/*` 做对照实验会把被测的那条路由整个遮掉，
  得到"glob 匹配不上"的**假结论**（我第一版诊断脚本就踩了）。
