### 0. 为什么做这一轮（真人录像的两个结构问题）

上一轮 PRP-F2（`ca3fb43`）技术闭环成立，但**真人验收未通过**：

1. **流程不是单变量实验**：第二场结束后仍能进 CHOICE、继续 +Day → 出现 `DAY 8/7`，
   同一强化可反复叠加。三个强化无法在**相同基础条件**下独立验证。
2. **双联炮是 shotgun workaround**：借用 `shotgun.fanAnglesDeg: [-4,4]` **同时**齐射两发，
   正常速度下两发轨迹高度重叠，玩家无法自然理解为「连续两发」。

真人裁决：重型弹头**方向通过**（冻结）；快速装填有趋势（待独立复验）；双联炮**不通过**（换表现机制）。

### 1. 必改 1｜流程收紧为严格单变量（`runPageState.ts`）

新增状态字段与常量：

- `RunPageState.battlesCompleted: number`（0 = 未打；1 = 只打完基础；2 = 验证结束）
- `RUN_MAX_BATTLES = 2`、`RUN_RESTART_LABEL = '重新开始验证'`
- `runVerificationComplete(s) => s.battlesCompleted >= RUN_MAX_BATTLES`

`pressRunAction` 的 RESULT 分支改为**分岔**：

| 场次 | 行为 |
|---|---|
| 第一场（`battlesCompleted < 2`） | `→ CHOICE`（保留**唯一一次**改装机会） |
| 第二场（`>= 2`） | **`return createRunPageState(ctx)`** = 全新 Run（DAY 3 / `buffs: []` / `modifier: null` / `battle: null`） |

- `runActionLabel`：终局 RESULT → `'重新开始验证'`；其余阶段文案不变。
- `chooseRunBuff` 加守卫：`if (s.modifier !== null || s.buffs.length > 0) return s;`
- `finishRunBattle` 第三行叙事按场次分岔：第一场「你发现了一次改装机会……」/ 终局「本次改装的验证到此结束。」
- `finishRunBattle` 每次 `battlesCompleted + 1`。

**结构后果**：`DAY 8/7`、多 Buff 累计、同一 Buff 重复堆叠在**结构上不可能**（不靠运行期检查）。

宿主侧（`runPage.ts`）无需新增清理逻辑：`apply()` 既有的
`if (next.phase === 'IDLE' && this.battle) this.endBattle();` 会在重置时 `dispose()` 旧运行时
→ Projectile / Contact / Battle Runtime 全清。

### 2. 必改 3｜Cannon 最小可复用 Burst（本 Queue **唯一**触碰正式 gameplay 的改动）

`src/battle/cannonBehavior.ts`：

- `CannonParams` 新增两个**可选**字段：`burstRounds`（默认 `1`）/ `burstIntervalMs`（默认 `0`）。
- `readCannonParams` 用新增的 `optNum()` 读取这两个字段：**缺失/非法 → 取默认值，不抛错**。
  ⚠️ 这是刻意的：6 个基准参数保持「缺失即抛错」，只有 burst 这两个可选 →
  **正式 `content.ts` 不用加任何字段**，默认行为逐帧不变。
- `stepFixed` 拆为三段：`连发间隔 → 主冷却 → emitRound()`
  - 连发期间**不并行递减冷却**（冷却只在最后一发之后开始计时 → 「一次攻击 = 一个整体」）；
  - `emitRound()`：打满 `burstRounds` 才进 `cooldownMs`，否则进 `burstIntervalMs` 发间隔。
- 新增 getter：`burstRounds` / `burstIntervalMs` / `roundsFiredSoFar` / `burstGapRemaining`。
- 连发的**每一发**都走同一条 `fire()` → 真实 projectile / 碰撞 / 伤害 / recoil / 生命周期。

**实测时序**（`FIXED_DT_MS = 1000/60`，口径 = 「新弹丸出现的固定步号差」）：

| 场景 | 第 1→2 发步差 | 换算 |
|---|---|---|
| 正式 `cannon`（`burstRounds=1`） | **60 步** | = 冷却 1000ms（回归零变化） |
| 双联炮（2 发 / `burstIntervalMs=100`） | **6 步** | = 100ms 连发间隔 |

**双联炮 overlay 改写**（`runModifiers.ts`）：

```
旧：behavior 'shotgun' + { fanAnglesDeg: [-4, 4] }   ← 同步齐射、轨迹重叠（真人判不通过）
新：behavior 'cannon'  + { burstRounds: 2, burstIntervalMs: 100 }
```

- 弹道**同向**（实测两发出生 y 差 < 3px），不再靠散射把两发分开；
- 渲染标记回到正式 cannon 弹丸（不再是 shotgun runtime 固定写死的 `'tracer'`）。

✅ 回归：`cannonScenarios / contentCannon / cannonBehavior / contactRouterProjectile / battleIntegration` = **27/27** 全绿。
