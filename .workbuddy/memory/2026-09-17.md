# PRP-VALIDATION-HUB-R1（验证中心 · 纯测试壳）

## 做了什么

新增独立导航壳 `validation-hub.html` + `npm run dev:validation`：把**三个已验证入口**
（Full Run = `run-page.html` / Next Run = `next-run.html` / Encounter Batch = `encounter-lab.html`）
摆到一页上，`一次启动 → 连续切换 → 一段录像批量验收`。

- `validationHub.ts`：三入口**唯一数据源**（纯数据，**该文件零 import**）+ `next()` 循环 +
  `read/writeValidationHubLastEntry`（可注入 store，便于测隐私模式分支）。
- `validationHubMain.ts`：页面壳（**只有导航**：0 画布、0 数据面板；卡片是真实 `<a href>`；
  `pageshow` 重读「上次进入」标记）。
- `validation-hub.html`：第六个根目录 HTML 入口（原型侧第五个）。
- `package.json`：`dev:validation` / `e2e:validation-hub`（**`dev` 未动**）。
- `vite.portrait-lab.config.ts`：新增 `validation-hub` input。
- `constants.ts` 删除清单 + `portraitDefaultEntry.test.ts` R2-03/R2-10（五 → 六入口）。

## 关键设计判断（已写进 §5.9 / REF §I）

**切换 = 整页导航**（真实 `<a>` 到入口页面**本身**），**不是**在 Hub 里 new 一套宿主：

1. Full Run 的入口就是玩家正式页面本身（= 根路径重写落地页，同一个文件）⇒ 另造宿主会丢保真度；
2. 文档销毁 ⇒ Runtime / 弹丸 / 接触 / 计时器 / 监听器 / Run-local state **一起消失**，宿主忘不掉；
3. 不复制第二套宿主逻辑（避免 Hub 版与独立版两套口径）。

**代价**：入口页面里没有「返回」按钮（加它就要改正式玩家页面）⇒ 返回 = 浏览器后退。
Queue 原文明确允许这种降级（「优先稳定，不为『单页切换』做底层重构」）。
