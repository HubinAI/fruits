## 关键事实 / 坑（已写入 MEMORY §5.8 + REF §H）
1. **`PlanckBattleOrchestrator.dispose()` 只是「丢弃引用」**（`PlanckWorld` 无显式销毁）
   ⇒ 被释放的实例**仍可被继续 step**（实测 240 → 241 步）。清理**不靠对象变惰性**，
   靠**宿主生命周期**：控制器 dispose 后把 `runtime` 置 `null`、循环随即退出。
   ⚠️ 一开始写成「dispose 后读数不再变化」是**错的**，已按真相改写断言。
2. **开局读数必须构造时固化**：RAF 一启动物理就前进，「t=0 的干净开局」页面上抓不到第二遍。
3. **`toEqual` 比较键集**：`{...fresh, 覆盖}` 与 `COMMON` 键数不同（19 vs 15）永远不相等 →
   必须写 `commonOf()` 只取 15 个同名字段。
4. **浮点不能四舍五入后再去重**：`ProtoRusher` 563.663 与 `RangedTurret` 564.0 取整后都是 564。
5. **HTML 注释里的说明文字会命中字符串守卫** → 与 R2-09 同口径，**剥 HTML 注释**再匹配。
6. **「不写战斗数值」的守卫要用正则**（`\b(hp|damage|cooldownMs|…)\s*[:=]\s*-?\d`），
   用 `includes('damage:')` 会被 `damage: cr.damage` 这种**合法只读赋值**误伤。
